# Бэкенд системы управления ЖЦИ

Серверная часть дипломного проекта. Стек: **Node.js + Express + SQLite**.

## Что нужно установить один раз

**Node.js версии 20 или выше.** Если ещё не установлен:

- Скачай LTS-версию с https://nodejs.org/ru/download — обычная программа-установщик.
- После установки открой терминал (на Windows — PowerShell или cmd) и проверь:
  ```
  node --version
  npm --version
  ```
  Должны показать версии. Если показывают — всё ок.

## Структура проекта

Положи папку `backend` рядом с твоим фронтендом, например:
```
diploma-project/
├── frontend/        ← твой React-проект (с DigitalPassportPLM.jsx)
└── backend/         ← эта папка
    ├── server.js
    ├── database.js
    ├── schema.sql
    ├── seed.sql
    ├── package.json
    ├── routes/
    └── (database.db и uploads/ создадутся при первом запуске)
```

## Запуск (первый раз)

В терминале:

```
cd путь/к/backend
npm install
npm start
```

Что произойдёт:
1. `npm install` скачает зависимости (Express, SQLite-драйвер, multer для файлов). Займёт минуту-две, создастся папка `node_modules`.
2. `npm start` запустит сервер. При самом первом запуске автоматически создастся файл `database.db` с таблицами и демо-данными (двумя моторами АИР 132M4).
3. В консоли увидишь:
   ```
   [database] Первый запуск: создание таблиц и начальное заполнение...
   [database] БД успешно инициализирована.
   [server] Сервер запущен: http://localhost:4000
   ```

## Проверка, что работает

Открой в браузере: **http://localhost:4000/** — должен увидеть JSON со списком эндпоинтов.

Открой: **http://localhost:4000/api/products** — должен увидеть массив из двух демо-моторов.

Открой: **http://localhost:4000/api/products/1** — увидишь полную карточку первого мотора со всеми характеристиками, событиями ЖЦ, обслуживанием и данными графика.

## Запуск (каждый следующий раз)

```
cd путь/к/backend
npm start
```

`npm install` повторно делать не нужно — он нужен только при первой установке или после изменения списка зависимостей.

## Остановка сервера

В терминале, где запущен сервер, нажми `Ctrl + C`.

## Режим разработки (с автоматическим перезапуском)

```
npm run dev
```

В этом режиме сервер сам перезапускается, когда ты меняешь код. Удобно при разработке.

## Куда что сохраняется

- `database.db` — файл базы данных. Содержит все изделия, события, обслуживание и т.д. **Этот файл — твоя БД, береги его.**
- `uploads/products/<id>/` — папки с загруженными документами по каждому изделию.

Чтобы **сбросить базу к чистому состоянию** (с демо-данными), просто удали файл `database.db` и перезапусти сервер.

## Возможные проблемы

**`'npm' не является внутренней или внешней командой`** — Node.js не установлен или не прописан в PATH. Переустанови Node.js, при установке оставь галочку «Add to PATH».

**`Error: listen EADDRINUSE :::4000`** — порт 4000 уже занят (другой сервер запущен). Либо останови тот другой процесс, либо измени порт в `server.js` (переменная `PORT`).

**`npm install` зависает или ошибки сети** — проверь интернет. Если на корпоративной сети, может понадобиться настроить прокси для npm.

## Список API-эндпоинтов

| Метод  | Путь                                | Что делает                              |
|--------|-------------------------------------|------------------------------------------|
| GET    | `/api/products`                     | Список всех изделий (краткие данные)     |
| GET    | `/api/products/:id`                 | Полная карточка изделия                  |
| POST   | `/api/products`                     | Создать изделие                          |
| PUT    | `/api/products/:id`                 | Обновить изделие                         |
| DELETE | `/api/products/:id`                 | Удалить изделие (каскадно всё связанное) |
| GET    | `/api/lifecycle-stages`             | Справочник этапов ЖЦ                     |
| POST   | `/api/products/:id/documents`       | Загрузить файл к изделию                 |
| GET    | `/api/documents/:id/download`       | Скачать файл                             |
| DELETE | `/api/documents/:id`                | Удалить файл                             |

## Следующий шаг

Когда бэкенд успешно запустился — подключаем к нему фронтенд (на следующей итерации).
