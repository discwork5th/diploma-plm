# Развёртывание на VPS

Пошаговая инструкция: от покупки сервера до работающего сайта с HTTPS.
Займёт около часа, если всё пойдёт гладко.

## Как это устроено

```
Браузер ──HTTPS──> Caddy (порты 80/443) ──> app (Node.js, порт 4000) ──> /data (база и документы)
```

- **Docker-образ** — «упакованное» приложение: Node.js, код и собранный фронтенд. Собирается по `Dockerfile`.
- **Контейнер** — запущенный образ. Их два: `app` (наше приложение) и `caddy` (веб-сервер).
- **Caddy** принимает запросы из интернета, сам получает бесплатный HTTPS-сертификат Let's Encrypt и передаёт запросы в `app`.
- **Том (volume) `plm-data`** — постоянный диск для базы и загруженных документов. Контейнер можно пересобрать или удалить, данные останутся.
- **docker-compose.yml** описывает, какие контейнеры запустить и как их связать. Всё поднимается одной командой.

## 1. Сервер

Нужен VPS с **Ubuntu 24.04**, минимум **1 vCPU и 2 ГБ памяти** (сборка фронтенда на 1 ГБ может не уместиться, см. «Если что-то пошло не так»).
После покупки у тебя будут **IP-адрес** и **пароль root**.

## 2. Домен

Сертификат HTTPS выдаётся на домен, а не на IP. Два варианта:

- **Свой домен** (.ru стоит пару сотен рублей в год). В панели регистратора создай A-запись: имя `@` (или поддомен, например `plm`), значение — IP сервера. Обновление записи может занять от нескольких минут до пары часов.
- **Бесплатно, без покупки:** сервис sslip.io превращает IP в домен. Для IP `203.0.113.5` домен будет `203-0-113-5.sslip.io`. Ничего настраивать не нужно, он сразу указывает на твой сервер. Для старта годится, для показа лучше свой домен.

## 3. Подключение к серверу

На Windows открой PowerShell:

```powershell
ssh root@IP_СЕРВЕРА
```

При первом подключении спросит про отпечаток ключа: пиши `yes`. Пароль при вводе не отображается, это нормально.
Дальше все команды выполняются уже на сервере.

## 4. Подготовка сервера

```bash
apt update && apt upgrade -y                               # обновить систему
apt install -y docker.io docker-compose-v2 git ufw         # Docker, Compose, git, файрвол
docker --version && docker compose version                 # проверка: должны показать версии
```

Файрвол: оставляем открытыми только SSH и веб.

```bash
ufw allow OpenSSH
ufw allow 80
ufw allow 443
ufw enable        # спросит подтверждение: y
```

> Важно: `ufw allow OpenSSH` до `ufw enable`, иначе сам себя отключишь от сервера.

## 5. Код

```bash
git clone -b portfolio https://github.com/discwork5th/diploma-plm.git
cd diploma-plm
```

Пока репозиторий приватный, git спросит логин и пароль. Вместо пароля нужен токен:
GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens → доступ только к `diploma-plm`, права Contents: Read-only.

## 6. Настройки

```bash
cp .env.example .env
nano .env                       # впиши DOMAIN=твой.домен, сохранить: Ctrl+O, Enter, выйти: Ctrl+X

cp backend/.env.example backend/.env
nano backend/.env               # ИИ-подбор: раскомментируй блок DeepSeek или Ollama и впиши ключ
```

Без настроек модели сайт работает, просто ИИ-подбор будет в режиме поиска по каталогу.

## 7. Запуск

```bash
docker compose up -d --build    # собрать образ и запустить в фоне; первый раз несколько минут
docker compose ps               # оба контейнера должны быть в статусе running
docker compose logs -f app      # логи приложения (выйти: Ctrl+C)
```

Открывай `https://твой.домен`. При первом запуске база создаётся с демо-каталогом.

## Повседневные команды

| Что сделать | Команда |
|---|---|
| Обновить сайт после изменений в git | `git pull && docker compose up -d --build` |
| Посмотреть логи | `docker compose logs -f app` (или `caddy`) |
| Перезапустить | `docker compose restart` |
| Остановить | `docker compose down` (данные сохранятся) |
| Сделать копию базы | `docker compose cp app:/data/database.db ./backup-$(date +%F).db` |
| Сбросить к демо-данным | `docker compose down && docker volume rm diploma-plm_plm-data && docker compose up -d` |

## Если что-то пошло не так

**`docker compose up` не может скачать образы (`Forbidden`, `timeout` при загрузке `node` или `caddy`).**
С некоторых серверов Docker Hub недоступен. Подключи зеркало:
```bash
echo '{ "registry-mirrors": ["https://mirror.gcr.io"] }' > /etc/docker/daemon.json
systemctl restart docker
```
У многих хостеров есть своё зеркало Docker Hub, адрес ищи в их документации.

**Сайт не открывается по HTTPS.** Смотри `docker compose logs caddy`. Обычно причина одна из трёх: домен ещё не указывает на IP (проверка: `ping твой.домен`), закрыты порты 80/443, в `.env` опечатка в DOMAIN.

**Сборка падает с `Killed` или зависает.** Не хватает памяти. Добавь файл подкачки на 2 ГБ и повтори сборку:
```bash
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

**ИИ-подбор пишет «модель недоступна».** Смотри `docker compose logs app`, там будет причина: неверный ключ (401), нет денег на балансе (402), неправильный адрес. Ollama, запущенная прямо на сервере, из контейнера доступна по адресу `http://host.docker.internal:11434/v1`, а не `localhost`. Сама Ollama при этом должна слушать не только localhost: переменная `OLLAMA_HOST=0.0.0.0` в её настройках (и порт 11434 не открывать в файрволе наружу).
